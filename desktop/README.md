# AI Office Desktop

내 PC에서 돌아가는 AI 에이전트 팀입니다. 모드는 셋입니다.
- **코드 작업**: AI 셋이 기획 → 구현 → 테스트 → 리뷰 → 수정을 나눠 맡고, 마지막 승인은 사람이 합니다.
- **보안 점검**: 의존성 부품 목록(SBOM)과 알려진 취약점으로 우선순위 보고서를 만듭니다.
- **자소서**: 내 경험·활동과 회사 공고·자소서 항목을 넣으면, 경험만 근거로 쓰고 심사관 5명의 점수가 기준을 넘을 때까지 고칩니다.
GitHub 버전 AI Office와 같은 원칙으로, 서버 없이 Windows 프로그램 하나로 동작합니다.

## 시작하기
1. 릴리스에서 **`AIOfficeDesktop-Setup.exe`**(설치 파일)를 받아 실행합니다. 관리자 권한 없이 내 계정에만 설치되고, 시작 메뉴와 (선택) 바탕화면에 바로 가기가 생깁니다.
   - 설치 없이 쓰려면 `AIOfficeDesktop.exe` 하나만 받아 실행해도 됩니다.
   - 서명되지 않은 프로그램이라 처음 실행할 때 Windows SmartScreen 경고가 뜰 수 있습니다. "추가 정보 → 실행"을 누르세요.
2. **전용 앱 창**이 뜹니다. Windows에 기본으로 깔린 Microsoft Edge의 앱 모드로 열리며, 주소창·탭이 없고 평소 쓰는 브라우저와 로그인·확장 프로그램이 섞이지 않습니다. Edge·Chrome이 없으면 기본 브라우저 탭으로 엽니다.
   - 창을 닫으면 프로그램도 끝납니다. AI 작업이 돌고 있으면 끝난 뒤에 종료합니다. 왼쪽 아래 **프로그램 종료** 버튼도 있습니다.
   - 이미 켜져 있을 때 다시 실행하면 같은 프로그램의 창을 하나 더 엽니다.
   - 오류 기록: `%APPDATA%\AIOfficeDesktop\log.txt`
3. 맨 위 탭에서 **코드 작업 / 보안 점검 / 자소서**를 고르고, 왼쪽에서 역할별 AI와 API 키를 넣습니다.

키 없이 흐름만 보려면 역할 AI를 모두 "테스트용 가짜 AI"로 고르세요.

**지우기**: Windows 설정 → 앱에서 AI Office Desktop 제거. 설정·키(`%APPDATA%\AIOfficeDesktop`, 자격 증명 관리자)와 자료 폴더(`문서\AIOffice자소서`)는 남습니다. 완전히 지우려면 두 폴더와 자격 증명 관리자의 `AIOfficeDesktop` 항목을 직접 지우세요.

## 흐름
| 단계 | 하는 일 |
|--|--|
| 팀장 | 요청을 작업 최대 3개로 나누고, 작업마다 읽을 파일을 고릅니다. 파일은 고치지 않습니다. |
| 개발 | 작업마다 파일을 고칩니다. 편집은 작업 폴더 안에서만 적용됩니다. |
| 테스트 | 설정한 테스트 명령을 실행합니다. |
| 리뷰 | 바뀐 내용과 테스트 결과를 보고 승인하거나 고칠 점을 적습니다. 파일은 고치지 않습니다. |
| 수정 라운드 | 리뷰가 고칠 점을 적거나 테스트가 실패하면, 정한 횟수만큼 개발이 다시 고칩니다. |
| 사람 | **변경 보기**로 diff를 확인하고 **승인** 또는 **버리기**를 누릅니다. |

승인을 누르면 작업 폴더가 git 저장소일 때 `ai-office/날짜-시각` 새 브랜치에 바뀐 파일만 커밋합니다. git 저장소가 아니면 파일만 바뀐 채로 둡니다.
버리기를 누르면 이번 작업에서 바뀐 파일을 모두 원래대로 되돌립니다.

## 보안 점검 모드
작업 폴더의 의존성 잠금 파일로 **부품 목록(SBOM)** 을 만들고 알려진 취약점에 등급을 매깁니다. 코드는 바꾸지 않습니다.

| 단계 | 하는 일 | 근거 |
|--|--|--|
| 부품 목록 | `requirements*.txt`(`==` 고정), `Pipfile.lock`, `poetry.lock`, `package-lock.json` → CycloneDX 1.5 | 잠금 파일 |
| 취약점 | 패키지·버전으로 알려진 취약점과 고쳐진 버전 조회 | api.osv.dev |
| 악용 여부·확률 | 실제 악용 목록 포함 여부, 30일 내 악용 확률 | CISA KEV, FIRST EPSS |
| 등급 | 심각도·악용 확률·외부 노출·데이터 등급·사용 흔적 각 0~3점, 15점 만점. KEV+노출+사용 흔적이면 **긴급**, 11점 이상 **우선**, 7~10 **주시**, 나머지 **정기** | 규칙 (AI 아님) |
| 조치안 | 긴급·우선 상위 8건만 AI가 이유·조치·티켓 제목을 씀. 추천 버전이 PyPI·npm에 실제 있는지 확인 | 보안 조치안 AI |

- 결과는 작업 폴더 `ai-office-security/`에 `sbom.cdx.json`, `report.json`, `report.md`로 남습니다.
- AI에는 패키지 이름·버전·취약점 정보만 보내고 소스 코드는 보내지 않습니다.
- **사용 흔적은 import 문 검색**입니다. 실제로 그 함수가 호출되는지는 보장하지 않습니다. 직접 import가 없어도 다른 패키지를 거쳐 쓰일 수 있어 0점이 아니라 1점을 줍니다.
- **수정 맡기기**를 누르면 고쳐진 버전이 확인된 긴급·우선 항목만 코드 작업 요청으로 옮겨 적습니다. 시작은 사람이 누르고, 결과는 diff 확인 후 승인합니다.
- 지원하지 않는 것: 범위 지정 버전(`>=`), Java·Go 등 다른 언어, 컨테이너 이미지. 키 없이 쓰는 공개 API라 회사 방화벽에서 막힐 수 있습니다.

## 자소서 모드
처음 켜면 **처음 설정 안내**가 뜹니다: ① AI 하나 고르고 키 넣기(키 확인 버튼) → ② 경험 넣기 → ③ 공고 넣기. 위쪽 체크리스트(AI 키 · 경험 · 작성 가이드 · 지원서)로 무엇이 남았는지 보입니다.

**사진·PDF·글로 넣기** — 세 곳 모두 같은 상자에 끌어다 놓거나, 눌러서 고르거나, 캡처를 **Ctrl+V**로 붙여 넣습니다.
| 넣는 곳 | 넣을 것 | AI가 하는 일 |
|--|--|--|
| ① 내 경험·활동 | 보고서·발표 자료·포트폴리오 PDF, 상장·활동 사진, 메모 | 경험 양식(기간·팀·내 역할·문제·한 일·결과·증거)으로 정리. 자료에 없는 것은 `[확인 필요]`, 마지막에 면접 꼬리질문 |
| ② 작성 가이드 | 취업 특강 슬라이드 사진·PDF, 책·필기 | 절 단위 정리본(`## 1. 제목 [p.N]`), 예시 문장은 베끼기 검사용으로 따로 |
| ③ 지원서 | 채용 공고 캡처·PDF, 자소서 문항 화면 캡처 | 회사·직무·마감·공고 원문(글자 그대로)·문항·글자수·공백 포함 여부 |
- 받는 파일: 사진(png·jpg·webp), PDF, txt·md, docx. 한글(.hwp)은 PDF로 저장해서 넣으세요. 한 번에 30 MB까지, 큰 사진은 긴 변 2000px로 줄여 보냅니다.
- 결과는 입력 칸만 채우고 **저장하지 않습니다.** 읽고 고친 뒤 저장하세요. 못 읽은 부분은 `[판독 불가]`로 남기고, 글자수·세는 방식이 안 보이면 알려 줍니다.
- 넣은 원본은 자료 폴더 `_원본/날짜-종류/`에 그대로 보관합니다.
- 사진·PDF는 고른 '사진·PDF 읽기' AI 회사로 전송됩니다.

**GitHub에서 가져오기** — for_office를 쓰던 사람은 경험·지원서·가이드를 한 번에 가져올 수 있습니다 (아래 '가져오기' 참고).

**③ 지원서 · 자소서** (작성·심사)
- 회사·직무·마감, 방산 여부, **회사 공고 원문**, 회사 정보(출처 있는 것만), **자소서 항목**(이름·원문·글자수·공백 포함/제외/바이트), 근거로 쓸 경험을 넣고 저장합니다.
- **AI로 작성 + 심사**: 작성 → 서류 심사 + AI 작성 확인 → 수정을 기준(AI 의심 ≤ 2, 심사 평균 ≥ 3.5, 규칙 오류 0)을 넘을 때까지 반복합니다. 결과는 답 칸에 채워지고, 읽고 고친 뒤 저장합니다.
- **서류 심사** (공고 기준, 글은 고치지 않음): 인사담당·현업 팀장·면접관·경쟁 지원자·공고 대조 5명이 문항마다 통과/보류/탈락과 1~5점을 매깁니다.
  - **서류 판정**: 탈락 표가 하나라도 있으면 *탈락 위험*, 모든 문항 평균 3.5 이상·AI 의심 2 이하·담당업무와 자격요건에 근거 없는 항목이 없으면 *통과 가능*, 나머지는 *보류*.
  - **공고 항목별 충족 여부**: 공고의 담당업무·자격요건·우대사항을 하나씩 뽑아 충족/부분/없음과 자소서 근거 위치를 표로 보여 줍니다.
  - 면접관은 경험 기록과 다른 수치·역할, 시뮬을 실측처럼 쓴 곳을 찾고 꼬리질문을 남깁니다.
- **AI 작성 확인** (글은 고치지 않음): AI가 쓴 글처럼 보이는 정도를 두 가지로 봅니다.
  - 규칙 신호(프로그램이 셈): 본문 괄호, 연결어 남발(또한·나아가·~를 통해), 추상 명사(역량·가치·성장), 문단 끝 다짐·교훈형, 셋씩 묶는 나열, 지나치게 고른 문장 길이, '하였습니다' 반복, 숫자 없음.
  - AI 판별관 1명: 문항마다 0~5점과 의심 문장, 왜 의심인지, 경험 기록 안에서 고칠 방향.
  - 서류 심사의 면접관 AI 점수와 판별관 점수 중 높은 쪽을 기준으로 씁니다. 실제 기업이 쓰는 AI 판별 도구와 결과가 다를 수 있습니다.
- 답 칸 글자수는 근거 표시 `[EXP-01]`·`[공고]`를 뺀 실제 제출 글자수입니다. **제출용 복사** 버튼은 근거 표시를 뺀 글을 복사합니다.
- 규칙 점검(AI 아님): 글자수, 첫 줄 `[소제목]`과 숫자, 본문 괄호, '하였습니다' 5회 이하, 다양한·열정·노력 합계 3회 이하, 없는 경험 번호, 같은 경험을 여러 항목에 쓴 경우, 근거 표시 없는 문단.

**작성 가이드 (취업 특강 정리본)**
- for_office의 `guides/G1-…md`(방산기업 서류특강), `G2-…md`(현대차그룹 서류특강)를 가져와 씁니다. 이 프로그램에는 들어 있지 않고 내 자료 폴더에서만 읽습니다.
- 문항 유형을 자동으로 나누고, for_office CLAUDE.md 표와 같은 절을 골라 작성 AI와 심사관 모두에게 줍니다.

  | 문항 유형 | 따르는 절 |
  |--|--|
  | 경험 (직무역량·도전·성공/실패·협업) | G1 §1 경험 쓰기, §6 항목별 구조(+따라 하면 안 되는 부분), G2 직무역량 |
  | 지원동기·입사 후 포부 | G2 지원동기, G2 §4 JD 읽는 법 |
  | 강점·약점 | G2 강점·약점 |
  | 시사·산업 / 인재상·가치 / 이력서 칸 | G2 해당 절 |
  | 방산 기업에 체크하면 모든 문항 | + G1 §2 방산 어필, §3 역량 한 조각, §4 직무별 키워드·도구 |
  | 모든 문항 공통 | G2 §1 대원칙, G1 §5 글쓰기 원칙, §7 FAQ, §8 퇴고 체크, G2 §5 합격 자소서 관찰 |
- 지원서 화면의 항목마다 "유형 · 따를 가이드"가 표시됩니다. 심사관은 가이드 위반을 지적할 때 `[G2 p.28]`처럼 쪽을 붙입니다.
- 가이드는 쓰는 방법의 근거일 뿐, 경험·수치·회사 정보의 근거가 아닙니다. 규칙과 다르면 규칙이 우선입니다 (소제목 필수, 다짐형 맺음 금지).
- **강의 예시 베끼기 검사**: `guides/sources/examples.txt`가 있으면 공백·문장부호를 뺀 20자 이상이 예시와 같을 때 규칙 오류로 막습니다 (for_office check.py와 같은 방식). 예시 원문은 AI에 보내지 않습니다.

**저장 위치** — 왼쪽 **자료 폴더** (기본 `문서\AIOffice자소서`)
```
experiences/EXP-01-제목.md
applications/<회사>-<직무>/app.json, 공고.md, 회사정보.md, Q1.md(근거 표시), Q1.제출용.txt, 심사기록/
guides/G1-….md, G2-….md, sources/examples.txt   작성 가이드
_지운것/   지운 경험 (되살릴 수 있게)
```
for_office 저장소 폴더를 자료 폴더로 고르면 기존 `experiences/` 기록을 그대로 씁니다. 기존 파일 이름은 바꾸지 않습니다.

**주의**
- 작성·심사를 누르면 공고·항목·고른 경험이 고른 AI 회사로 전송됩니다. 무료 요금제는 입력이 사람 검토·학습에 쓰일 수 있으니 주민번호·연락처는 적지 마세요.
- 심사관 5명은 같은 AI 모델이 역할만 바꿔 보는 것이라 사람 5명만큼 독립적이지 않고, 점수는 같은 글도 회차마다 ±1 정도 흔들립니다.

## 가져오기 · 다음에 켤 때
- **⓪ 가져오기**: GitHub 버전(for_office)의 `experiences/` 경험 기록과 `applications/`·`final/`·`jd/` 지원서·공고·답을 그대로 가져옵니다. 다시 정리할 필요 없습니다.
  - 방법 셋: GitHub 저장소에서 바로(비공개면 토큰), 내려받은 zip, 내 PC의 clone 폴더
  - `final/<지원서>/`가 있으면 그 답을 씁니다. `_template`, `_검사-*`는 건너뜁니다.
  - 바뀌는 파일은 먼저 `_백업/날짜-시각/`에 복사합니다. 이 프로그램에서 고른 근거 경험·목표 점수는 다시 가져와도 유지합니다.
  - "켤 때마다 GitHub에서 최신본 가져오기"를 켜면 실행할 때 한 번 자동으로 받습니다.
- 모든 지원서·답·심사 기록은 자료 폴더에 파일로 저장되고, **마지막으로 연 탭·지원서·경험**은 설정에 저장돼 다음에 켜면 그대로 열립니다. 지원서를 열면 지난 심사 결과도 다시 보여 줍니다.

## 안전 장치
**화면 서버**
- 이 PC(127.0.0.1)에서만 열립니다. 다른 PC에서는 접속할 수 없습니다.
- 실행할 때마다 새 토큰을 만들고, 토큰은 브라우저 주소의 `#` 뒤로만 넘깁니다. 화면 HTML에는 토큰이 없어, 같은 PC의 다른 프로그램이 화면을 받아 가도 API를 쓸 수 없습니다.
- 모든 API는 토큰 헤더가 있어야 합니다. 다른 웹사이트는 이 헤더를 붙여 요청할 수 없습니다(브라우저가 막음).
- 주소 이름(Host)이 127.0.0.1·localhost가 아니면 거절합니다. 악성 사이트가 자기 도메인을 127.0.0.1로 바꿔 접근하는 DNS 리바인딩 공격을 막습니다.
- 요청 크기 5 MB 제한, 화면을 다른 사이트 안에 끼워 넣지 못하게 막는 보안 헤더.

**파일**
- 코드 작업은 작업 폴더 밖 경로, 절대 경로, `.git` 안쪽을 읽지도 쓰지도 않습니다.
- 가져오기는 압축을 디스크에 풀지 않고 정해진 이름의 파일만 읽습니다. 링크·장치 파일, 바깥 경로(`../`)는 무시하고, 파일 하나 2 MB·전체 50 MB로 제한합니다.

**AI**
- AI는 셸 명령을 직접 실행하지 않습니다.
- 코드 작업의 테스트는 AI가 바꾼 코드를 내 PC에서 실행하는 단계라 **기본으로 꺼져 있습니다**. 작업 폴더의 파일이나 붙여 넣은 글에 숨은 지시(프롬프트 인젝션)가 있으면 AI가 위험한 코드를 쓸 수 있기 때문입니다. 내가 만든 저장소처럼 믿을 수 있는 폴더에서만 켜세요.
- 한 번 실행에 AI 호출 수 한도가 있습니다. 기본값은 12회입니다.

**키·토큰**
- AI 키와 GitHub 토큰은 Windows 자격 증명 관리자에 저장하고, 화면으로 다시 보내지 않습니다.
- GitHub 토큰은 Fine-grained token으로 저장소 하나, Contents 읽기 전용, 만료일을 정해 만드세요.

**배포 파일**
- 릴리스에 `AIOfficeDesktop.exe.sha256`을 같이 올립니다. 받은 뒤 PowerShell에서 `Get-FileHash AIOfficeDesktop.exe`로 값이 같은지 확인하세요.
- 코드 서명은 아직 없습니다. SmartScreen 경고가 뜨고, 백신이 오탐할 수 있습니다.

## API 키와 비용
- 키는 Windows 자격 증명 관리자에 저장합니다. 저장이 안 되는 환경에서는 `%APPDATA%\AIOfficeDesktop\keys.json`에 저장하고 화면에 그 위치를 표시합니다.
- 키는 각 회사 API로만 보내고, 화면에 다시 표시하지 않습니다.
- **요금은 키 주인에게 청구됩니다.** 실행이 끝나면 역할별 호출 수와 입력·출력 토큰 수를 화면에 보여 줍니다.
- 모델 이름은 각 회사 문서에서 확인해 넣으세요. 기본값은 예시이고, 회사가 모델을 바꾸면 달라질 수 있습니다.

## 한계
- 큰 저장소는 파일 목록과 고른 파일 내용만 보냅니다. 한 번에 보내는 파일 내용은 약 12만 자까지입니다.
- 텍스트 파일만 다룹니다. 이미지·바이너리 파일은 보지 않습니다.
- AI가 고친 코드는 틀릴 수 있습니다. 승인 전에 diff를 꼭 확인하세요.

## 직접 빌드
```bat
cd desktop
pip install pyinstaller -r requirements.txt
python -m unittest -v tests/test_desktop.py tests/test_modes.py
pyinstaller --onefile --windowed --icon app.ico --name AIOfficeDesktop --version-file version_info.txt --add-data "aio_desktop/static;aio_desktop/static" --hidden-import keyring.backends.Windows run.py
iscc installer.iss          # 설치 파일 (Inno Setup 6)
```
소스로 바로 실행: `python -m aio_desktop` (desktop 폴더에서). 평소 브라우저 탭으로 열려면 `--browser`.
