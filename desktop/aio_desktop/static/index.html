대기 중
GitHub 버전(for_office)에 정리해 둔 experiences/ 경험 기록과 applications/·jd/·final/ 지원서를 그대로 가져옵니다. 따로 다시 정리할 필요 없습니다. 바뀌는 파일은 먼저 자료 폴더 _백업에 복사합니다. 이 프로그램에서 고른 근거 경험·목표 점수는 유지합니다.
토큰은 Fine-grained token으로, 저장소는 이 저장소 하나만, 권한은 Contents: Read-only 하나만, 만료일을 정해서 만드세요. 쓰기 권한 토큰은 넣지 마세요.
작성 가이드 = for_office의 guides/ 특강 정리본(G1·G2). 문항 유형에 맞는 절을 골라 작성·심사에 쓰고, guides/sources/examples.txt가 있으면 강의 예시 베끼기 검사도 합니다. 가이드는 이 프로그램에 들어 있지 않고 내 자료 폴더에서만 읽습니다.

    


    

      
자소서는 여기 적은 경험만 근거로 씁니다. 적지 않은 수치·역할은 AI가 지어내지 않고 [확인 필요]로 남깁니다. 시뮬레이션과 실측은 꼭 구분해 적으세요.

      
자료로 경험 만들기 보고서·발표 자료·포트폴리오 PDF, 상장·사진, 메모를 넣으면 AI가 아래 양식으로 정리합니다.
        

      

      
      
      
      

    


    

      
작성 가이드는 '어떻게 쓰는지'의 기준입니다 (취업 특강, 책, 학교 취업센터 자료 등). 작성 AI와 심사관이 문항 유형에 맞는 부분을 골라 씁니다.
        경험·수치·회사 정보의 근거로는 쓰지 않습니다. 가이드에 나온 예시 문장은 베끼기 검사에만 씁니다.

      

      
가이드 넣기 강의 슬라이드 사진·PDF나 글을 넣으면 AI가 절 단위로 정리하고, 예시 문장은 따로 모읍니다.
        

      

      
      
      
예시 문장 (베끼기 검사용, AI에 보내지 않음)

      

      
'## 문항별: 지원동기'처럼 제목에 문항 유형을 넣으면 그 유형 문항에만 적용되고, 나머지 절은 모든 문항에 적용됩니다.

    


    

      

      
공고 넣기 채용 공고 캡처·PDF와 자소서 문항 화면 캡처를 넣으면 회사·직무·마감·공고 원문·문항·글자수를 채웁니다. 공고 원문은 글자 그대로 옮깁니다.
